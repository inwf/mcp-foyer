工具名称上游名称说明模型使用操作
call_tool内置Call a tool on one of the servers behind this endpoint by server name, tool name and arguments, whether or not the tool is in this tool list. The arguments are checked against the tool's input schema before forwarding, and the result is returned as the tool produced it. Skip discovery when server, tool and arguments are already known. This endpoint's own four tools are called directly, not through call_tool.
get_tool_details内置Complete input schema, description and annotations of one tool, named by server and tool. Use before call_tool when the arguments are not yet known and the search did not include the schema.
list_servers内置Overview of the servers behind this endpoint: each one's name, state, description, tool and resource counts, and the error when it is down. Use it to see which servers are connected and which are broken; to find a tool, search_tools matches the capability directly, and search_tools(server) lists what one server offers.
search_tools内置Find tools on the servers behind this endpoint by describing the capability, or browse one server by giving server alone. Most tools are not in this tool list and are only reachable this way; every hit can then be called with call_tool(server, tool, args). Results are ranked best first, five per page by default, each hit naming the arguments the tool requires; includeSchema=true returns each hit's complete input schema so the call can be prepared from the same result. The query describes what a tool does; the particular thing to act on — a repository, a person, a file name — goes into call_tool's arguments, since no tool is named after it. Words that matched nothing are reported in unmatched; words too common to tell tools apart (the, what, my) are ignored, so a query made only of them comes back empty and names them. A query naming one server searches that server alone and reports it in server; a cross-server search spreads its hits, at most two per server unless only one matched; browse one server to see all it has. Servers that are not connected are named in unavailable, up to five, with unavailableMore counting the rest; browsing one gives the reason.

append_file未暴露Append text to the end of a file, creating the file if it does not exist. The existing content is never changed or replaced. The text is appended exactly as given, with no newline added before or after it, so end it with a newline if the next append should start on a new line. Only works within allowed directories.未被使用

If the destination exists, the operation will fail: it never overwrites. Both source and destination must be within allowed directories.未被使用
create_directory未暴露Create a new directory or ensure a directory exists. Can create multiple nested directories in one operation. If the directory already exists, this operation will succeed silently. Perfect for setting up directory structures for projects or ensuring required paths exist. Only works within allowed directories.未被使用
directory_tree未暴露Get a recursive tree view of files and directories as a JSON structure. Each entry includes 'name', 'type' (file/directory), and 'children' for directories. Files have no children array, while directories always have a children array (which may be empty), except at the last level when 'depth' limits the tree: those directories are not read and have no children array. The output is formatted with 2-space indentation for readability. Only works within allowed directories.未被使用
edit_file未暴露Make line-based edits to a text file. Edits apply in order, each to the result of the ones before it, and each replaces the first match of its oldText with newText. oldText must match the file's text exactly, except that line endings (LF or CRLF) never matter and, when there is no exact match, a run of whole lines matches if each line is equal once leading and trailing whitespace is ignored (newText then takes the file's indentation). Whitespace inside a line must match. If any edit has no match, nothing is written and the error shows the closest lines of the file, numbered, to copy oldText from. Returns a git-style diff showing the changes made. Only works within allowed directories.未被使用
get_file_info未暴露Retrieve detailed metadata about a file or directory. Returns comprehensive information including size, creation time, last modified time, permissions, type and hard-link count. This tool is perfect for understanding file characteristics without reading the actual content. Only works within allowed directories.未被使用
list_allowed_directories未暴露Returns the list of directories that this server is allowed to access. Subdirectories within these allowed directories are also accessible. Use this to understand which directories and their nested paths are available before trying to access files.未被使用

Use it to see what a directory contains; when you also need each entry's size or want entries sorted by size, use list_directory_with_sizes instead, and for a recursive view use directory_tree. Returns one line per entry. Only works within allowed directories.未被使用

Only works within allowed directories.未被使用
